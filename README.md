# 페비 데스크톱 펫

바탕화면을 돌아다니는 작은 캐릭터입니다. 더블클릭하면 로컬에서 도는 Ollama 모델과 말풍선으로 대화합니다.

캐릭터가 돌아다니는 것만 볼 거라면 1번과 4번만 하면 됩니다. 대화까지 하려면 2~3번도 필요합니다.

> 함께 들어 있는 `assets/phoebe`는 **샘플**입니다. 유튜브 채널 [@phoebe-chobi](https://www.youtube.com/@phoebe-chobi)의 팬 캐릭터 "페비쵸비"(원작: 명조)를 참고해 AI로 만든 그림이라, 개인적으로 써 보는 용도로만 쓰고 다시 배포하지는 말아 주세요. 만든 과정은 아래 [샘플 그림을 만든 방법](#샘플-그림을-만든-방법)에 있습니다.

## 설치

### 1. uv 설치

Windows 10/11 기준입니다. PowerShell에서:

```
winget install astral-sh.uv
```

파이썬은 따로 설치하지 않아도 됩니다. 처음 실행할 때 uv가 맞는 버전(3.12)과 필요한 패키지를 알아서 받습니다.

### 2. Ollama 설치

```
winget install Ollama.Ollama
```

설치 후 시작 메뉴에서 Ollama를 한 번 실행해 둡니다(트레이에 아이콘이 생깁니다).

### 3. 내 PC에 맞는 대화 모델 고르기

대화 모델은 그래픽카드 메모리(VRAM)에 통째로 올라가야 빠릅니다. 먼저 VRAM을 확인합니다.

- **작업 관리자** → 성능 → GPU → "전용 GPU 메모리"
- 또는 NVIDIA 카드라면 PowerShell에서 `nvidia-smi`

아래 표에서 고릅니다. 크기는 대략적인 값이고, 정확한 목록은 [ollama.com/library/qwen3](https://ollama.com/library/qwen3)에 있습니다.

| 내 VRAM | 고를 모델 | 내려받는 크기 | 비고 |
|---|---|---|---|
| 그래픽카드 없음, 4GB 이하 | `qwen3:4b` | 약 2.6GB | CPU로도 돌지만 답이 느립니다. 말투가 덜 자연스럽습니다 |
| 6GB | `qwen3:4b` | 약 2.6GB | 여유 있게 돕니다 |
| 8GB | `qwen3:8b` | 약 5.2GB | **이 프로젝트를 만든 환경**(RTX 2060 SUPER). 실사용 6.2GB, 초당 약 50토큰 |
| 12GB | `qwen3:14b` | 약 9.3GB | 말투와 업무 답변이 더 좋아집니다 |
| 16GB | `qwen3:14b` | 약 9.3GB | 여유 있게 돕니다 |
| 24GB 이상 | `qwen3:30b` 또는 `qwen3:32b` | 약 19~20GB | |

고르는 기준은 "내려받는 크기 + 1~2GB가 VRAM보다 작을 것"입니다. 모자라면 일부가 일반 메모리로 넘어가 몇 배 느려집니다.

고른 모델로 `phoebe` 모델을 만듭니다. `qwen3:8b`가 아니라면 **`Modelfile`의 첫 줄을 먼저 고칩니다.**

```
FROM qwen3:8b      ← 여기를 고른 모델로 (예: FROM qwen3:14b)
```

그다음 이 폴더에서:

```
ollama pull qwen3:8b
ollama create phoebe -f Modelfile
```

(`pull` 뒤의 이름도 고른 모델로 바꿉니다.)

잘 올라갔는지는 대화를 한 번 한 뒤 `ollama ps`로 봅니다. `PROCESSOR`가 `100% GPU`면 맞게 고른 것이고, `CPU`가 섞여 있으면 한 단계 작은 모델로 바꾸거나 `Modelfile`의 `num_ctx 8192`를 `4096`으로 줄인 뒤 `ollama create`를 다시 합니다.

Qwen이 아닌 다른 모델(예: `gemma3`, `exaone` 등)을 써도 됩니다. `FROM` 줄만 바꾸면 되고, 말투는 `Modelfile`의 `SYSTEM`과 `MESSAGE` 예시가 정합니다.

### 4. 실행

`run.bat`을 더블클릭하면 콘솔 창 없이 실행됩니다. 처음에는 패키지를 받느라 1~2분 걸립니다. 터미널에서 띄우려면:

```
uv run python -m phoebe_pet
```

Ollama가 꺼져 있거나 `phoebe` 모델이 없어도 캐릭터는 돌아다닙니다. 말을 걸면 말풍선으로 무엇이 없는지 알려 줍니다.
대화 모델을 처음 부를 때는 메모리에 올리느라 답이 1~2분 걸리고, 그 뒤로는 바로 답합니다.

## 조작

| 동작 | 결과 |
|---|---|
| 누른 채 끌기 | 집어 듭니다. 들려 있는 동안 바둥거리고, 세게 휘두르면 그쪽으로 기울어집니다. 놓으면 마우스 속도대로 던져집니다 |
| 더블클릭 | 입력창이 열립니다. Enter로 보내고 Esc로 닫습니다. Shift+Enter는 줄바꿈 |
| 말풍선 클릭 | 내용을 클립보드에 복사합니다 |
| 우클릭, 트레이 아이콘 | 일시정지, 대화 초기화, 숨기기, 개발자 패널, 종료 |

**개발자 패널**은 동작마다 버튼이 있는 작은 창입니다. 맨 위에는 지금 상태, 기운·심심함·기분 수치와 기분 이름, 다음 혼잣말까지 남은 시간이 보입니다. "지금 말하기"를 누르면 바로 한마디 하고(`monologue = false`여도 됩니다. 다만 말하기 곤란한 때는 안 합니다), "기분 바꾸기"를 누르면 기분을 하나씩 돌아가며 고정합니다. 한 바퀴 돌면 원래 기분으로 돌아갑니다. 버튼을 누르면 캐릭터가 그 동작을 바로 합니다(벽·천장 동작은 그 자리로 옮겨 가고, `fall`은 화면 위에서 떨어뜨립니다). `talk`, `drag`처럼 프로그램이 상황에 따라 고르는 동작은 6초 동안 보여 준 뒤 원래대로 돌아갑니다. "고른 동작 반복"을 켜면 끝나도 계속 다시 시작해서 그림을 오래 볼 수 있습니다.

긴 답이나 코드는 스크롤되는 큰 말풍선으로 뜨고, `복사`와 `닫기` 버튼이 붙습니다.
전체 화면 프로그램을 쓰는 동안에는 캐릭터가 숨습니다.

## 설정 (`config.toml`)

| 항목 | 기본값 | 설명 |
|---|---|---|
| `character` | `phoebe` | `assets/` 아래 캐릭터 폴더 이름. `placeholder`로 바꾸면 임시 캐릭터 |
| `scale` | `1.0` | 크기 배율 (0.25 ~ 4.0) |
| `model` | `phoebe` | Ollama 모델 이름 |
| `ollama_url` | `http://localhost:11434` | Ollama 주소 |
| `speed` | `1.0` | 이동 속도 배율 (0.25 ~ 4.0) |
| `monologue` | `true` | 몇 분마다 기분과 상황에 맞춰 짧게 혼잣말을 합니다. 끄면 말만 안 하고 기분에 따른 움직임은 그대로입니다 |
| `monologue_minutes` | `[4, 10]` | 혼잣말 간격(분). `[최소, 최대]` 사이에서 무작위로 정합니다 |
| `history_turns` | `12` | 모델에 보내는 최근 대화 턴 수 |
| `keep_alive` | `30m` | 모델을 메모리에 유지하는 시간 |

설정을 바꾼 뒤에는 앱을 다시 실행합니다.

## 성격

캐릭터는 숫자 세 개로 된 기분을 갖고 있고, 천천히 변합니다.

- **기운**: 낮 동안 조금씩 닳고(밤에는 두 배, 뛸 때도 더 빨리), 눕거나 졸 때 차오릅니다. 실행한 시각에 따라 시작 값이 다릅니다(아침에 가장 높고 밤에 가장 낮습니다).
- **심심함**: 마우스가 가까이 없으면 쌓이고, 가까이 있으면 줄어듭니다. 건드리거나 대화를 하면 크게 줄어듭니다.
- **기분**: 대화하면 좋아지고, 세게 던지거나 1초 넘게 붙잡혀 있으면 나빠집니다. 가만두면 보통 상태로 돌아옵니다.

이 값들로 기분 이름(졸림, 삐짐, 심심함, 신남, 평온)이 정해지고, 기분에 따라 다음에 고르는 동작이 달라집니다. 졸리면 눕거나 졸고, 신나면 뛰어다니는 식입니다. 시간은 실제 시계를 따르므로 숨겨 두거나 전체 화면 프로그램을 쓰는 동안에도 흘러갑니다.

기분별 동작 배율(`[affinity.<동작>]`), 상황별 몸짓(`[gestures]`), 모델이 늦거나 꺼져 있을 때 쓰는 예비 대사(`[lines]`)는 `personality.toml`에 있습니다. 캐릭터 폴더(`assets/<이름>/`)에 `personality.toml`을 두면 `actions.toml`처럼 그쪽이 우선합니다.

### 혼잣말

`monologue_minutes` 간격(기본 4~10분)마다 한마디 합니다. 심심하면 더 일찍, 졸리면 더 늦게 합니다. 던져진 직후, 잠에서 깬 직후, 1초 넘게 붙잡혀 있다가 놓인 직후, 낮 12시·저녁 6시·밤 11시에도 잠시 뒤에 한마디 합니다. 이런 일 하나하나에는 10분에 한 번까지만 말합니다. 한 문장이 작은 말풍선으로 뜨고 저절로 사라집니다.

모델이 6초 안에 말을 시작하지 않거나 15초 안에 끝내지 못하면, Ollama가 꺼져 있으면, 또는 답을 쓸 수 없거나 최근에 한 말과 같으면 `personality.toml`의 예비 대사를 대신 씁니다. 이때 오류 말풍선은 뜨지 않습니다. 대화 중이거나 입력창이 열려 있을 때, 숨김·일시정지·끌려가는 중, 전체 화면 프로그램이 앞에 있을 때는 말하지 않습니다.

### 몸짓

상황마다 몸짓이 하나씩 있고, 그 상황의 대사를 할 때 같이 합니다.

| 상황 | 몸짓 |
|---|---|
| 졸림 | 하품하고 눈을 비빕니다 |
| 삐짐 | 볼을 부풀리고 고개를 돌립니다 |
| 심심함 | 발끝으로 바닥을 두드리며 몸을 흔듭니다 |
| 신남 | 두 손을 모으고 가볍게 통통 뜁니다 |
| 평온 | 짧게 기도합니다 |
| 던져진 뒤 | 머리를 감싸 쥐고 어지러워합니다 |
| 잠에서 깰 때 | 엎드려서 기지개를 켭니다(일어나는 동작의 일부) |
| 놓인 뒤 | 가슴에 손을 얹고 한숨을 쉽니다 |
| 낮 12시 | 배를 문지르며 쑥스러워합니다 |
| 저녁 6시 | 어깨 높이로 손을 흔듭니다 |
| 밤 11시 | 졸린 눈으로 손을 흔들다 꾸벅입니다 |

몸짓이 있는 대사는 캐릭터가 서 있을 때 나옵니다. 하던 동작은 끝내고, 말할 차례가 되면 서 있는 채로 기다립니다. 던져진 뒤와 놓인 뒤의 대사는 60초, 낮·저녁·밤 인사는 10분까지 기다리고 그래도 못 서면 건너뜁니다. 기분 대사는 설 때까지 기다립니다. 기분 몸짓은 말없이도 그 기분일 때 가끔 합니다. 몸짓은 `personality.toml`의 `[gestures]`에, 기분별 배율은 `[affinity.gesture_<기분>]`에 있습니다. `placeholder` 캐릭터에는 몸짓이 없어서 예전처럼 바로 말합니다. 개발자 패널에는 서기를 기다리는 대사가 "기다리는 대사"로 보입니다. 패널의 "지금 말하기"도 몸짓이 있는 대사면 설 때까지 기다렸다가 말합니다.

`monologue = true`이면 캐릭터가 실행되는 내내 대화 모델이 `keep_alive` 설정으로 GPU에 올라가 있습니다. GPU를 비우려면 `monologue = false`로 둡니다. 말만 안 할 뿐, 기분에 따른 움직임은 그대로입니다.

## 캐릭터 바꾸기

시메지(Shimeji) 규격 이미지 세트를 그대로 쓸 수 있습니다.

1. `assets/<이름>/` 폴더를 만들고 `shime1.png`, `shime2.png` … 를 넣습니다. 투명 배경 PNG이고, 캐릭터는 왼쪽을 봅니다.
2. `config.toml`의 `character`를 `<이름>`으로 바꿉니다.
3. (선택) 폴더에 `actions.toml`을 함께 넣으면 기본 `actions.toml` 대신 그 파일을 씁니다. 그림 이름은 자유라서, `walk01.png` … `walk32.png`처럼 여러 장짜리 동작을 `frames`에 나열할 수 있습니다.

`shime1.png`만 있어도 실행됩니다. 없는 그림은 가장 비슷한 동작의 그림으로 대신합니다.
말할 때와 생각할 때 전용 그림을 쓰려면 `talk1.png`, `talk2.png`, `think1.png`, `think2.png`를 추가합니다.

### 스프라이트 시트에서 가져오기

여러 포즈를 격자로 그린 그림 한 장을 잘라서 넣을 수 있습니다. 배경 제거, 크기 통일, 발 위치 맞춤까지 해 줍니다.

```
uv run python tools/import_sheet.py sheet.png --grid 5x2 --names 1,2,3,4,11,21,7,8,13,23 --character phoebe
```

- `--grid`: 가로x세로 칸 수.
- `--names`: 왼쪽 위부터 읽는 순서로 각 칸의 그림 번호. 건너뛸 칸은 `-`, 말하기·생각은 `talk1`, `think1`.
- `--bg`: 배경색. 기본값 `auto`는 테두리 색을 배경으로 봅니다. `#00ff00`처럼 직접 지정하거나, 이미 투명한 그림이면 `none`.
- `--tolerance`: 배경색과 얼마나 달라도 배경으로 볼지(기본 40). 배경이 남으면 올리고, 캐릭터가 깎이면 내립니다.

결과 폴더의 `_preview.png`에서 잘린 모습을 확인할 수 있습니다. 배경은 캐릭터에 없는 색의 단색으로 그리는 것이 좋습니다.

자주 쓰는 번호: 1 서기, 2·3 걷기, 4 떨어지기, 11 앉기, 21 눕기, 7·8 집혀서 기울어짐(9·10은 더 크게), 5·6 버둥거림, 13 벽 매달리기(12·14 오르기), 23 천장 매달리기(24·25 이동), 18·19 착지.

`assets/placeholder`는 임시 캐릭터이고 `uv run python tools/make_placeholder.py`로 다시 만들 수 있습니다.
그 밖의 캐릭터 폴더는 git에 올라가지 않습니다.

## 샘플 그림을 만든 방법

`assets/phoebe`의 그림 501장은 전부 로컬 PC(RTX 2060 SUPER 8GB, RAM 32GB)에서 AI로 만들었습니다. 클라우드 서비스는 쓰지 않았습니다. 순서는 이렇습니다.

| 단계 | 한 일 | 도구 | 걸린 시간 |
|---|---|---|---|
| 1 | 참조 그림 14장 모으기 | 영상 캡처, ffmpeg | |
| 2 | 캐릭터 LoRA 학습 | kohya sd-scripts, Illustrious-XL v1.0 | 약 40분 |
| 3 | 포즈별 정지 그림 생성 | ComfyUI + LoRA | 장당 약 23초 |
| 4 | 정지 그림을 움직이는 영상으로 | ComfyUI + Wan 2.2 I2V | 영상당 4~10분 |
| 5 | 프레임 자르기, 배경 제거, 크기 맞춤 | Python (Pillow) | 1~2분 |

**1. 참조 그림.** 캐릭터가 나오는 영상에서 또렷하고 자세가 서로 다른 장면 14장을 잘랐습니다. 정면·옆·뒤, 서기·앉기·발차기가 섞이게 골랐고, 팔다리를 편 정자세 그림은 필요 없었습니다. 긴 변 400~640픽셀이면 충분했습니다.

**2. LoRA 학습.** 애니메이션 그림용 SDXL 모델인 Illustrious-XL v1.0 위에 캐릭터 LoRA를 학습했습니다. 그림마다 자세·표정·배경만 적은 캡션을 달고, 생김새(머리, 눈, 옷)는 일부러 적지 않아 호출어 `phoebechobi`에 묶이게 했습니다. 설정은 rank 8, 해상도 768, 14장 × 10회 반복 × 10에포크 = 1400스텝, 학습률 1e-4, AdamW8bit, fp16이고 VRAM 7.7GB를 썼습니다.

**3. 정지 그림.** 포즈마다 `phoebechobi, 1girl, solo, chibi, full body, <포즈 태그>, simple background, green background` 형태의 프롬프트로 1024×1024 그림을 2장씩 뽑아 좋은 쪽을 골랐습니다. 배경을 단색 초록으로 둔 것은 나중에 지우기 쉽게 하기 위해서입니다. 끌려갈 때 기울어지는 그림 4장은 한 장을 좌우로 돌려 만들었습니다.

**4. 움직이는 동작.** 그림을 한 장씩 따로 뽑으면 장마다 생김새가 조금씩 달라 이어지지 않습니다. 그래서 정지 그림을 영상 생성 모델 Wan 2.2 I2V(14B, Q4_K_S 양자화 + 4스텝 Lightning LoRA)의 **시작 장면이자 끝 장면**으로 주고 "제자리에서 걷는다" 같은 문장으로 480×480, 33프레임 영상을 만들었습니다. 시작과 끝이 같은 그림이라 끊김 없이 반복됩니다.

처음에는 동작마다 다른 정지 그림에서 출발했는데, 그림마다 등신이 달라 서 있다가 걸으면 머리가 갑자기 작아졌습니다. 그래서 바닥 동작은 **서 있는 그림 한 장에서 이어 만들었습니다.** 먼저 끝 장면 없이 "옆으로 돌아서 걷는다", "앉는다" 같은 전환 영상을 만들고, 자세가 자리 잡은 프레임을 다음 반복 영상의 시작이자 끝 장면으로 씁니다. 서기 → 앉기 → 눕기 → 잠들기처럼 계속 이어 가면 모든 동작의 머리 크기와 등신이 같아지고, 자세 사이를 잇는 전환 동작도 함께 얻습니다(되돌아가는 전환은 같은 프레임을 거꾸로 재생). 버둥거리기, 떨어지기, 벽 오르기, 천장 매달리기는 끌려가거나 던져질 때만 나와서 각자의 정지 그림으로 만들고 크기만 맞췄습니다. 팔이 짧아 손이 머리 위로 올라가지 않으므로, 천장에서는 `build.py`가 양손에 짧은 밧줄을 그려 넣어 밧줄을 잡고 매달리게 합니다.

몸짓 클립(`g_*`)은 서 있는 그림에서 만들고, 엎드려 기지개 켜는 클립(`g_woke`)은 엎드린 자세에서 이어 만들어 잠에서 깰 때 뒤에 붙였습니다.

**5. 자르기.** 프레임마다 가장자리 색을 배경으로 보고 지운 뒤, 그림자나 `zzz` 같은 떨어진 조각을 버리고 128×128 투명 PNG로 저장했습니다. 바닥 동작은 모두 같은 영상 좌표에 있으므로 **배율 하나와 발 기준선 하나**로 자릅니다. 동작마다 배율을 따로 잡으면 동작이 바뀔 때 크기가 튑니다. 누운 자세는 몸이 틀보다 길어서 조금 줄이는데, 눕는 전환 동안 서서히 줄여 눈에 띄지 않게 했습니다. 공중·벽 동작은 한 동작의 32장을 같은 상자와 같은 배율로 자르고, 머리 크기가 바닥 동작과 같아지도록 동작별 크기를 정했습니다.

쓴 스크립트는 `tools/imagegen/`에 참고용으로 넣어 두었습니다. 만든 PC의 경로(`D:\study\ComfyUI`)가 그대로 적혀 있어서, 쓰려면 경로를 고쳐야 합니다.

| 파일 | 하는 일 |
|---|---|
| `train/prepare.py`, `train/dataset.toml`, `train/train.ps1` | 캡션 작성과 LoRA 학습 |
| `gen.py`, `gen_set.py` | 정지 그림 한 장 / 포즈 전체 생성 |
| `vid.py`, `vid_set.py` | 동작 영상 하나 / 전체 생성 |
| `build.py` | 프레임을 잘라 `assets/phoebe`와 그 안의 `actions.toml` 만들기 |

### 직접 만들어 보려면: PC 사양별 선택

필요한 저장 공간은 ComfyUI 약 2GB, 그림 모델 약 6.5GB, 영상 모델 약 24GB입니다.

| 내 VRAM | 정지 그림 (SDXL + LoRA) | 움직이는 동작 (Wan 2.2 I2V) |
|---|---|---|
| 6GB 이하 | 느리게나마 가능하지만 LoRA 학습은 어렵습니다 | 권하지 않습니다. 정지 그림만 써도 펫은 동작합니다 |
| 8GB | 가능 (위 수치가 이 환경) | Q4_K_S 양자화로 가능. RAM 32GB 권장. 더 가볍게는 Q3_K_S(파일당 약 6GB) |
| 12GB | 여유 | Q5 양자화, 또는 해상도 640 |
| 16GB 이상 | 여유 | fp8 원본(파일당 13GB)이나 Q8, 720p까지 |

- 그림을 만드는 동안에는 대화 모델을 메모리에서 내려야 합니다. 8GB에서는 둘을 같이 올릴 수 없습니다.
- AI 없이 하려면 격자로 그린 그림 한 장을 위의 `tools/import_sheet.py`로 잘라 넣으면 됩니다. 클라우드 이미지 생성 서비스로 포즈 시트를 한 번에 뽑는 것이 가장 손이 덜 갑니다.
