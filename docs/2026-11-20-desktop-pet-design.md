# 페비 데스크톱 펫 설계

작성일: 2026-11-20

## 의도

로컬에서 도는 Qwen 기반 `phoebe` 모델(Ollama)에 "몸"을 붙인다. 작은 2D 캐릭터가 Windows 바탕화면 위를 돌아다니고, 클릭하면 말풍선으로 대화할 수 있다. 용도는 캐릭터 채팅과 가벼운 업무 비서(요약, 초안, 번역, 코드 질문).

처음에는 Slack 봇으로 계획했으나, 사용자가 데스크톱에서 돌아다니는 캐릭터 쪽을 원해 방향을 바꿨다. Slack 연결은 이 설계 범위가 아니다.

## 목표

- 캐릭터가 화면을 스스로 돌아다니며, 동작이 **자연스럽고 다양**하다. (사용자가 직접 강조한 요구)
- 마우스로 집어 들고, 던지고, 떨어뜨릴 수 있다.
- 더블클릭하면 대화창이 열리고(한 번 누른 채 끌면 집어 들기, 한 번 클릭만으로는 아무 일도 없음), 답이 말풍선으로 글자가 흘러나오듯 표시된다.
- 캐릭터 그림은 폴더의 이미지 파일만 바꾸면 교체된다.

## 하지 않는 것 (1차 버전)

- 음성 출력·음성 입력
- 도구 호출(일정·Jira 연동 등 실제로 뭔가를 실행하는 비서 기능)
- 다른 프로그램 창 위에 올라타 걷기 (화면 가장자리와 작업 표시줄만 지형으로 취급)
- 여러 캐릭터 동시 실행, 캐릭터 복제
- Live2D·3D
- 대화 기록의 영구 저장 (앱을 끄면 사라짐)

## 실패로 보는 것

- 캐릭터가 일하는 데 방해가 된다: 클릭을 가로채거나, 전체 화면 프로그램 위에 뜨거나, 포커스를 빼앗는 것.
- 동작이 뚝뚝 끊기거나 같은 패턴만 반복해 기계적으로 보이는 것.
- CPU를 눈에 띄게 쓰는 것. 기준은 작업 관리자에 보이는 전체 CPU 사용률이다. 캐릭터가 멈춰 있을 때(서기·앉기·눕기) 1% 이하, 움직이는 중에도 3% 이하. 멈춰 있는 동안에는 갱신 주기를 낮추고, 마우스 근접·전체 화면 감지는 느린 주기로 따로 확인한다.

## 제약

- Windows 11, RTX 2060 SUPER(VRAM 8GB). 모델이 약 6.2GB를 쓰므로 앱은 GPU를 쓰지 않는다.
- Python 3.12, uv 설치되어 있음. Ollama 0.40.16이 `localhost:11434`에서 동작.
- 모델이 메모리에서 내려가 있으면 첫 답까지 1~2분 걸릴 수 있다.
- 페비 캐릭터 그림은 사용자가 직접 구해 넣는다. 저장소에는 임시 캐릭터만 들어간다.

## 접근 방법

| 방법 | 장점 | 단점 |
|---|---|---|
| **A. Python(PySide6) 자체 앱 + 시메지 이미지 규격 호환** (채택) | 걷기·기어오르기·낙하·끌려가기가 규격에 이미 정의됨. 기존 시메지 이미지 세트를 그대로 넣을 수 있음. 채팅·비서 기능 확장이 자유로움 | 동작 로직을 직접 구현 |
| B. 기존 Shimeji-ee(Java) 개조 | 동작이 이미 완성 | 오래된 코드, 채팅 연동과 확장이 어려움 |
| C. Godot 등 게임 엔진 | 애니메이션 편집 도구 | 투명 창·시스템 연동이 번거롭고 비서 기능에 불리 |

사용자가 방법 선택을 맡겼고, 작성자가 A를 골랐다. 근거: "자연스럽고 다양한 동작"은 그림 장수와 동작 로직에서 나오는데, A는 그림을 검증된 규격에 기대고 로직만 만들면 된다.

## 설계

### 창 구조

- **캐릭터 창**: 스프라이트 크기(기본 128×128)의 테두리 없는 투명 창. 항상 위, 작업 표시줄에 표시 안 함, 포커스를 가져가지 않음. 창 자체가 화면 위를 이동한다. 투명한 픽셀은 클릭이 뒤로 통과한다.
- **말풍선 창**: 캐릭터 머리 위에 붙어 따라다니는 별도 창. 페비의 답을 표시한다. 화면 밖으로 나가면 위치를 뒤집는다.
- **입력창**: 캐릭터를 더블클릭하면 캐릭터 옆에 뜨는 작은 입력 상자. Enter로 전송, Esc로 닫기.
- **트레이 아이콘**: 종료, 일시정지(돌아다니기 멈춤), 대화 초기화, 숨기기.
- 캐릭터 우클릭 메뉴도 같은 항목을 제공한다.
- 전체 화면 프로그램이 앞에 있으면 캐릭터를 숨긴다.

### 이미지 규격

- `assets/<캐릭터이름>/shime1.png` ~ `shime46.png`, 투명 배경 PNG. 시메지 표준 프레임 번호를 따른다(1~3 서기·걷기, 4 떨어지기, 5~10 끌려가기, 11 앉기, 12~14 벽 타기, 15~17 쪼그려 앉기, 18~19 착지, 20~21 눕기·기기, 22~25 천장, 26 올려다보기, 30~33 다리 흔들며 앉기 등).
- 위 번호 설명은 작성자의 기억에 의한 대략적인 예시다. 구현 전에 Shimeji-ee 원본의 기본 동작 정의(actions.xml)를 확인하고, 다르면 **실제 표준이 우선**이다. 실제 시메지 이미지 세트를 넣었을 때 올바른 그림이 나오는 것이 기준이다. 표준에 전용 프레임이 없는 동작은 가까운 프레임으로 대체한다.
- 왼쪽을 보는 그림이 기준이며, 오른쪽 이동 시 좌우 반전한다.
- 없는 프레임 번호는 가장 가까운 동작의 프레임으로 대체해, 장수가 적은 세트도 돌아가게 한다.
- 규격에 없는 "말하기"와 "생각 중"은 선택 프레임(`talk1.png`…, `think1.png`…)으로 받고, 없으면 서기·앉기 프레임으로 대체한다.
- 임시 캐릭터 세트는 스크립트로 그려서 만든다(단순한 도형 캐릭터). 그림 없이도 모든 동작을 확인할 수 있어야 한다.

### 동작

물리: 중력, 바닥(작업 영역 아래쪽 = 작업 표시줄 위), 좌우 벽과 천장(주 모니터 작업 영역 가장자리). 약 60fps 타이머로 위치를 갱신하고, 그림 프레임은 동작별 속도로 넘긴다.

동작 목록:

| 구분 | 동작 |
|---|---|
| 바닥 | 서 있기, 걷기, 달리기, 앉기, 다리 흔들며 앉기, 쪼그려 앉기, 눕기, 기어가기, 마우스 쳐다보기 |
| 벽·천장 | 벽 붙잡기, 벽 타고 오르내리기, 천장 매달려 이동, 손 놓고 떨어지기 |
| 공중 | 낙하, 착지(튕김), 던져져 날아가기 |
| 상호작용 | 집혀서 끌려가기(마우스 속도에 따라 몸이 기울어짐), 놓으면 마우스 속도로 던져짐 |
| 대화 | 생각 중(답 기다리는 동안), 말하기(답이 나오는 동안) |

자연스러움을 위한 규칙:

- 다음 동작은 현재 상태에서 갈 수 있는 것들 중 가중치 무작위로 고른다. 같은 동작이 연속으로 뽑히지 않게 한다.
- 지속 시간과 이동 거리는 범위 안에서 무작위. 걷기는 서서히 출발하고 서서히 멈춘다.
- 동작 사이에는 반드시 연결 동작을 거친다(예: 걷기 → 서기 → 앉기. 걷다가 바로 눕지 않는다).
- 한동안 건드리지 않으면 앉거나 눕는 쪽 가중치가 올라간다. 마우스가 가까이 오면 쳐다본다.
- 대화가 시작되면 하던 동작을 마무리하고 멈춰 서서 응답한다. 대화 중에는 돌아다니지 않는다.

동작 정의(프레임 순서, 속도, 가중치, 전이)는 코드에 박지 않고 데이터 파일 하나로 두어 조정하기 쉽게 한다.

### 대화

- Ollama `/api/chat`에 스트리밍으로 요청한다. 모델 `phoebe`, `think: false`.
- 대화 기록은 메모리에 유지하고, 최근 N턴만 보낸다(컨텍스트 8192 토큰 안에 들어가도록).
- 요청을 보낼 때 `keep_alive`를 길게 주어 모델이 내려가지 않게 한다.
- 답은 말풍선에 글자가 흘러나오듯 표시한다. 다 나온 뒤 일정 시간(글 길이에 비례) 후 사라진다. 긴 답(코드, 목록)은 말풍선 대신 스크롤 가능한 큰 풍선으로 표시하고, 클릭으로 복사할 수 있다.
- 네트워크 요청은 화면 갱신을 막지 않도록 별도 스레드에서 처리한다.
- Ollama가 꺼져 있거나 모델이 없으면 말풍선으로 상황을 알린다. 모델을 올리는 중이면 "생각 중" 동작을 유지한다.
- 가끔 먼저 말 걸기(혼잣말): 설정으로 켜고 끌 수 있고, 기본은 끔.

### 설정

`config.toml` 하나: 캐릭터 폴더, 크기 배율, 모델 이름, Ollama 주소, 이동 속도 배율, 혼잣말 여부.

## 구현자에게 맡기는 것

- 모듈 분리 방식, 동작 데이터 파일의 형식
- 구체적인 가중치·속도·시간 값 (돌려 보며 조정)
- 임시 캐릭터의 생김새
- 말풍선의 시각 디자인
- 테스트 범위: 동작 선택·물리 계산처럼 화면 없이 검증 가능한 부분은 단위 테스트를 둔다

## 작성자가 정한 것 (사용자가 직접 고른 것이 아님)

- Python + PySide6, uv로 의존성 관리
- 시메지 이미지 규격 호환
- 1차 버전에서 "다른 창 위에 올라타기"와 여러 모니터 지원 제외
- 대화 기록을 저장하지 않음
- 대화 열기는 더블클릭, CPU 기준 수치, 시메지 실제 표준 우선 (검토 과정에서 정함)
- 프로젝트 폴더는 기존 `D:\study\phoebe-slack-bot`을 그대로 쓴다(이름은 나중에 바꿀 수 있음)
