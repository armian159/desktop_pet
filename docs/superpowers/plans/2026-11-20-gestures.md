# 상황별 몸짓 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 대사 상황 11개마다 몸짓 영상을 만들고, 대사를 할 때 그 몸짓을 재생하며, 기분 몸짓은 말없이도 가끔 하게 한다.

**Architecture:** 영상은 기존 파이프라인(`tools/imagegen/vid_set.py` → ComfyUI Wan 2.2 → `build.py`)으로 만들어 `assets/phoebe`의 새 동작 `gesture_<키>`가 된다. `personality.toml`의 `[gestures]`가 상황 키를 동작에 잇는다. `PetApp`은 몸짓이 있는 대사를 페비가 서 있을 때까지 미루고(그동안 `Pet.hold_stand`로 서기에 머물게 함), 말풍선을 띄울 때 `Pet.play(동작)`으로 몸짓을 시작한다.

**Tech Stack:** Python 3.12, PySide6, Pillow, ComfyUI + Wan 2.2 I2V (로컬), pytest.

**Spec:** `docs/superpowers/specs/2026-11-20-gestures-design.md`

## Global Constraints

- 상황 키 11개: `sleepy, sulky, bored, happy, calm, thrown, woke, released, lunch, evening, late_night`.
- 서기 몸짓 동작 이름: `gesture_<키>` (woke 제외 10개). 기분 5개는 `weight = 1`, `idle_weight = 1`, `stand`의 `next`에 포함. 사건·시간 5개는 `weight = 0`, `idle_weight = 0`, 어느 `next`에도 없음. 모두 `surface = "floor"`, `speed = 0`, `frame_ms = 62`, 한 번만 재생, `next = ["stand"]`.
- `woke`는 `wake_up` 전환 동작 = 기존 `{to_sleep_r}` 뒤에 `g_woke` 프레임.
- 몸짓 대사 대기 한도: `thrown`, `released` 60초 / `lunch`, `evening`, `late_night` 600초 / 기분 키는 한도 없음.
- 틀 크기 128px, 배율과 발 기준선은 서 있는 그림 하나로(기존 `cut_floor`). 틀 크기는 바꾸지 않는다.
- 예비 대사: 상황마다 8줄, 해요체, 40자 미만, 방랑자님 한 번까지, 이모지·반말·말더듬 없음.
- 몸짓이 없는 캐릭터(placeholder)와 몸짓이 없는 상황은 지금 동작과 똑같다.
- `assets/phoebe`는 git에 없다. 스크립트와 코드만 커밋한다.
- 사용자에게 보이는 문구는 한국어 해요체, 코드 주석·식별자는 영어.

## Review Focus

### Task 4: Pet과 App 연결

**Files:** Modify `src/phoebe_pet/pet.py`, `src/phoebe_pet/app.py`, `src/phoebe_pet/dev_panel.py`; Test `tests/test_pet.py`, `tests/test_app.py`, `tests/test_dev_panel.py`

**Interfaces:**
- Consumes: `Personality.gestures` (Task 3).
- Produces:
  - `Pet.hold_stand: bool = False` — when true, choosing what follows `stand` returns `"stand"`.
  - `Pet.standing -> bool` — `mode is Mode.AUTO and action == "stand"`.
  - `Pet.play(self, name: str) -> None` — start action `name` now (mode AUTO, floor). Only valid while `standing`; otherwise no-op.
  - `PetApp(..., gestures: dict[str, str] | None = None)` — filtered to names in `pet.action_names()`.
  - `WAIT_LIMIT = {"thrown": 60.0, "released": 60.0, "lunch": 600.0, "evening": 600.0, "late_night": 600.0}`.
  - `PetApp.waiting_key -> str | None` (for the panel).
  - `DevPanel(..., waiting: Callable[[], str | None] | None = None)`; status shows `기다리는 대사: <키>` when not None.

Behaviour in `life_tick`, after the existing in-flight early return: `key = speaker.due()`.
- No key → release any wait (`hold_stand = False`, clear waiting).
- Key and not `can_speak()` → existing behaviour (drop events), and release the wait.
- Key with a gesture and not `pet.standing` → start/continue waiting: `pet.hold_stand = True`, remember `(key, clock())` (restart the clock if the key changed). If `key in WAIT_LIMIT` and waited longer than its limit → `speaker.drop_pending()`, release the wait.
- Otherwise → `speak(key)` (remember the key for the reply).

In `_show_speech`: if the spoken key has a gesture and `pet.standing` → `pet.play(gesture)`; then `pet.speaking = True` as today. Keep `hold_stand` on while the line is in flight and while the bubble shows; release it when the speech bubble closes, when the speech is dropped/skipped, and in `_stop_speaking`.
