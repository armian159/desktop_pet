# 성격과 스스로 하는 말·행동 설계

## 왜

지금 페비는 `actions.toml`의 고정 가중치로 동작을 무작위로 고르고, 성격(상냥함, 덜렁댐, 피자·구름 좋아함)은 `Modelfile`에만 있어 대화할 때만 드러난다.
혼잣말(`monologue`)은 기본으로 꺼져 있고, 켜도 15~40분마다 맥락 없이 한 문장을 말할 뿐이다. 말과 동작은 서로 연결돼 있지 않다.

목표는 **살아 있는 느낌**이다. 페비가 자기 사정(졸림, 심심함, 기분)을 가진 존재처럼 보여야 하고, 말과 행동이 같은 상태에서 나와야 한다.
예: 밤이 늦으면 앉았다가 눕고 졸다가 "슬슬 눈꺼풀이 무거워요..."라고 한다. 던지면 잠깐 삐지고, 한동안 혼자 두면 심심해서 돌아다닌다.

## 목표

- 시간과 사건에 따라 천천히 바뀌는 내부 상태가 있다.
- 상태가 동작을 고르는 확률을 바꾼다. 움직임은 모델과 관계없이 늘 즉시, 끊김 없이 이어진다.
- 페비가 몇 분에 한 번쯤 스스로 짧게 말한다. 말의 내용은 지금 상태와 상황(시간대, 방금 일어난 일)에서 나온다.
- 대사는 대화 모델이 만들고, 모델을 쓸 수 없거나 느리면 미리 써 둔 대사로 대신한다.
- 대부분의 순간은 말 없이 동작으로만 드러난다.

## 하지 않는 것

- 앱을 다시 켜도 상태와 기억이 이어지는 것 (상태는 시작할 때 시간대로부터 새로 정한다)
- 새 그림·새 동작 만들기. 지금 있는 동작만 쓴다
- 다른 프로그램 창이나 사용자가 하는 일을 읽고 반응하기
- 모델이 다음 동작을 직접 고르기
- 음성

## 피할 것 (돌아가도 실패인 것)

- 화면을 과도하게 가리는 것. 스스로 하는 말은 짧은 작은 말풍선으로만 띄우고 몇 초 뒤 저절로 사라진다. 스크롤 말풍선은 사용자가 말을 걸었을 때만 쓴다.
- 모델 답을 기다리느라 동작이 멈칫하는 것.
- 같은 대사를 연달아 하는 것.
- 사용자가 대화 중이거나, 숨겨 두었거나, 전체 화면 프로그램을 쓰는 중에 끼어드는 것.

## 검토한 방법

1. **규칙으로 상태 계산 + 써 둔 대사만 사용.** 즉시 반응하고 GPU를 쓰지 않지만, 며칠 지나면 같은 말이 반복된다는 게 보인다.
2. **규칙으로 상태 계산 + 대사는 모델이 상태를 보고 생성, 실패하면 써 둔 대사 (채택).** 움직임은 1번과 같아 모델에 의존하지 않고, 말은 매번 다르며 `Modelfile`의 성격을 그대로 살린다. 대신 모델이 GPU 메모리를 계속 차지한다(아래 "사용자가 정한 것").
3. **모델이 몇십 초마다 다음 동작과 말을 결정.** 모델이 늘 GPU에 올라가 있어야 하고 답을 기다리는 동안 멈칫하며, 고를 수 있는 동작은 어차피 정해져 있다. 비용에 비해 얻는 것이 적어 제외.

사용자가 2번을 골랐다.

## 사용자가 정한 것

- 목표는 살아 있는 느낌이다.
- 일하는 중에 스스로 말을 거는 것은 괜찮다. 화면을 과도하게 가리지만 않으면 된다.
- 방법은 2번이다.
- 대화 모델은 GPU에 늘 올려 둔다. 혼잣말 요청도 사용자 대화와 같은 `keep_alive`(기본 30m)를 보내고, 평소 간격(4~10분)이 그보다 짧으므로 페비가 켜져 있는 동안 모델은 내려가지 않는다. GPU를 비워야 할 때는 `monologue = false`로 끈다(README에 이 점을 적는다). 앱을 켤 때 모델이 아직 안 올라와 있으면, 첫 혼잣말 요청이 모델을 올리는 동안은 예비 대사가 나간다.

## 설계

아래는 모두 설계자(Claude)가 정한 것이며, 만드는 사람이 더 나은 값을 찾으면 바꿔도 된다. 수치는 시작값이다.

### 1. 상태 (`src/phoebe_pet/mood.py`, Qt 없음)

세 값, 모두 0~1.

| 값 | 오르는 때 | 내리는 때 |
|---|---|---|
| `energy` 기운 | 누워 있거나 졸 때(`lie`, `doze_off`, 잠자는 동작) 천천히 회복 | 깨어 움직이는 동안 천천히, 달리면 조금 더 빨리. 밤(23~6시)에는 더 빨리 |
| `boredom` 심심함 | 아무도 건드리지 않는 동안 천천히 | 대화, 집어 들기, 마우스가 가까이 오기 |
| `cheer` 기분 | 대화가 끝날 때, 칭찬받을 때(간단히: 대화가 성공적으로 끝나면 조금) | 세게 던져질 때, 오래 붙잡혀 버둥거릴 때. 시간이 지나면 0.6 쪽으로 서서히 돌아온다 |

- 시작값: `energy`는 시간대로 정한다(아침 0.8, 오후 0.6, 밤 0.3 정도). `boredom` 0.2, `cheer` 0.6.
- 상태는 **실제 시계**를 따라 바뀐다. 숨김·전체 화면·일시정지 중에도 계속 흐른다(두 시간 게임을 하고 돌아오면 그만큼 졸리고 심심하다). 그래서 `Pet.tick`(창 타이머, 숨기면 멈추고 `MAX_DT`로 잘림)이 아니라 `PetApp`의 1초 poll이 지난 실제 시간으로 `Mood.tick`을 부른다. 숨김·전체 화면 중에는 사람이 없는 것으로 보고 `boredom`이 오르고, `energy`는 깨어 있는 것으로 계산한다.
- 상태는 매 tick에 지난 시간만큼 바뀐다. 변화 속도는 한 시간 안팎에 눈에 띄게 달라지는 정도로 잡는다(예: 깨어 있으면 `energy`가 시간당 0.15 감소).
- 세 값에서 **지금의 기분 이름** 하나를 고른다: `sleepy`(energy < 0.3), `sulky`(cheer < 0.3), `bored`(boredom > 0.7), `happy`(cheer > 0.8), 그 밖은 `calm`. 겹치면 이 순서가 우선한다. 이름이 바뀔 때 약간의 여유(히스테리시스)를 두어 경계에서 깜빡이지 않게 한다.
- `Mood`는 `Pet`과 같은 방식으로 순수 파이썬 클래스이며 시간·난수·현재 시각을 주입받아 테스트할 수 있어야 한다.

사건은 `Mood`의 메서드로 들어온다: `on_chat_done()`, `on_grab()`, `on_throw(speed)`, `on_resist(seconds)`, `on_mouse_near()`, `tick(dt, action_name, now)`.
`Pet`이 이미 알고 있는 사건(잡기, 놓기 속도, 버둥거림, 현재 동작)은 `Pet`이 `Mood`에 알린다. 대화 사건은 `PetApp`이 알린다.

### 2. 동작 고르기에 반영

- 새 파일 `personality.toml`(루트). 캐릭터 폴더에 같은 이름의 파일이 있으면 그것을 쓴다(`actions_file`과 같은 규칙).
- 동작별로 기분 이름마다 배율을 적는다. 적지 않은 것은 1.

```toml
[affinity.lie]
sleepy = 4
bored = 0.5

[affinity.run]
sleepy = 0.1
happy = 3
bored = 2
```

- `Chooser.choose`가 기존 가중치(평소 / `idle_weight`)에 지금 기분의 배율을 곱한다. `actions.toml`의 구조는 바꾸지 않는다(`assets/phoebe/actions.toml`은 `tools/imagegen/build.py`가 만들어 git에 없으므로, 성격 값은 따로 두는 편이 덮어써질 걱정이 없다).
- `personality.toml`에 있지만 동작 표에 없는 이름은 무시한다(캐릭터마다 동작이 달라서). 배율이 음수면 시작할 때 오류.
- 기분은 다음 동작을 고를 때만 반영된다. 하던 동작을 중간에 끊지 않는다.

### 3. 스스로 하는 말

기존 `monologue` 흐름(`PetApp.idle_tick`)을 대체한다.

**언제 말하나**
- **평소**: 마지막으로 말한(사용자 대화든 혼잣말이든) 뒤 4~10분 사이 무작위 시점. 기분이 `bored`면 간격이 짧아지고 `sleepy`면 길어진다.
- **사건 직후** (각 30초~1분 안에, 사건 종류별로 10분에 한 번까지): 세게 던져져 착지, 졸다가 깨어남, 오래 버둥거린 뒤 내려놓임, 시간대 경계(12시 점심, 18시 저녁, 23시 이후 첫 번째).
- **말하지 않는 때**: 사용자 대화가 진행 중이거나 말풍선이 떠 있음, 입력창이 열려 있음, 숨김, 전체 화면, 일시정지, 지금 끌려가거나 공중에 있음. 이때 생긴 사건 대사는 버린다(나중에 몰아서 하지 않는다).

**무엇을 말하나**
- 모델에게 보내는 마지막 메시지를 상황 설명으로 만든다. 예:
  `(지금은 밤 11시 20분. 페비는 많이 졸리다. 방금 바닥에 누웠다. 방랑자님은 한동안 말이 없다. 페비가 혼잣말처럼 짧게 한 문장만 말한다. 20자 안팎.)`
  들어가는 것: 시각, 기분 이름을 풀어 쓴 말, 방금 사건이나 지금 동작, 마지막 대화로부터 지난 시간.
- 최근 대화 기록은 지금처럼 함께 보내되, 상황 설명 자체는 기록에 남기지 않는다.
- 혼잣말은 대화 기록에 **가장 최근 하나만** 남긴다(모델이 만든 것이든 예비 대사든, 사용자가 본 그대로). 새 혼잣말을 하면 이전 혼잣말 항목은 기록에서 지운다. 그래야 사용자가 "응?" 하고 답했을 때 모델이 자기가 뭐라고 했는지 알면서도, 혼잣말이 실제 대화를 기록 창(12턴) 밖으로 밀어내거나 반복을 부추기지 않는다. 반복 회피용 직전 10개 목록은 기록과 따로 둔다.
- 받은 답은 첫 문장만 쓰고 60자를 넘으면 자른다. 비었으면 예비 대사를 쓴다.
- 직전 10개의 혼잣말과 같은 문장이면 예비 대사로 바꾼다.

**예비 대사**
- `personality.toml`의 `[lines]`에 기분 이름별·사건별 목록을 둔다.

```toml
[lines]
sleepy = ["하암... 눈꺼풀이 무거워요.", "잠깐만 눈 좀 붙일게요..."]
bored = ["구름이라도 지나가면 좋을 텐데요.", "방랑자님, 바쁘세요?"]
thrown = ["앗, 깜짝이야! 너무해요...", "어, 어지러워요..."]
lunch = ["벌써 점심이에요! 피자 어떠세요?"]
# calm, happy, sulky, woke, released, evening, late_night ...
```

- 모델에게 요청하고 **6초** 안에 첫 글자가 오지 않거나 **15초** 안에 문장이 끝나지 않으면, 예비 대사를 바로 띄우고 그 요청의 답은 버린다. Ollama가 꺼져 있거나 모델이 없을 때도 조용히 예비 대사를 쓴다. 오류 문구는 띄우지 않는다.
- 버린 요청은 억지로 끊지 않는다(`urlopen`이 막혀 있으면 끊을 수 없다). 작업 스레드는 끝날 때까지 두되 결과는 무시하고, 그 스레드가 살아 있는 동안에는 새 혼잣말 요청을 보내지 않는다(예비 대사는 가능).
- 사용자 대화가 시작되면 진행 중인 혼잣말 요청은 버린 것으로 치고 대화를 바로 보낸다. 혼잣말 작업 스레드는 사용자 대화용 `self.worker`와 따로 둔다.
- 답이 왔을 때 "말하지 않는 때" 조건이 생겼으면(그 사이 끌려가거나 입력창이 열렸거나 숨겨짐) 띄우지 않고 버린다.
- 해당 목록이 없거나 비면 아무 말도 하지 않는다.

**어떻게 보이나**
- 스트리밍하지 않는다. 문장이 완성된 뒤 한 번에 작은 말풍선(`BubbleWindow`의 짧은 모드)으로 띄우고, 기존 `hide_delay_ms`대로 저절로 사라진다. 스크롤 모드로 넘어가지 않는다(60자 제한으로 보장).
- 동작은 바꾸지 않는다. 지금의 `Mode.TALK`(동작을 갈아치우고 벽에서 떨어뜨리며 끝나면 `stand`로 돌아감)는 쓰지 않는다.
- 대신 `Pet`에 "말하는 중" 표시를 둔다. 표시가 켜져 있고 지금 동작이 `stand`이면 그림만 `talk` 프레임으로 바꿔 보여 준다. 동작의 남은 시간은 그대로 흐르고, 다음 동작으로 넘어가면 자연히 원래 그림으로 돌아간다. 앉기·눕기·졸기·걷기·벽·천장에서는 그림을 바꾸지 않고 말풍선만 띄운다(누운 채 졸린 말을 하다가 벌떡 일어나 보이지 않도록).
- 모델 답을 기다리는 동안 동작은 평소대로 이어진다(`think` 그림으로 바꾸지 않는다).
- 사용자가 더블클릭해 입력창을 열면 떠 있던 혼잣말 말풍선은 닫고 대화로 넘어간다.

### 4. 설정 (`config.toml`)

| 항목 | 기본값 | 설명 |
|---|---|---|
| `monologue` | `true` (지금은 `false`) | 스스로 말하기. 끄면 말만 안 하고 상태와 동작 변화는 그대로 |
| `monologue_minutes` | `[4, 10]` | 평소 말하는 간격(분) |

기존 `MONOLOGUE_GAP`, `MONOLOGUE_PROMPT` 상수는 없앤다. README의 설정 표와 "조작" 절을 함께 고친다.

### 5. 개발자 패널

상단 상태 줄에 `energy / boredom / cheer`, 지금 기분 이름, 다음 혼잣말까지 남은 시간을 보여 준다. 버튼 두 개를 더한다: "지금 말하기"(간격을 무시하고 바로 한 번), "기분 바꾸기"(기분 이름을 차례로 강제해 동작 배율을 확인).

### 6. 테스트

- `Mood`: 시간 흐름에 따른 값 변화, 사건별 변화, 시간대 시작값, 기분 이름 판정과 히스테리시스.
- `Chooser`: 기분 배율이 곱해지는지, 없는 이름은 무시하는지, 음수 배율이면 오류인지.
- `personality.toml` 읽기: 캐릭터 폴더 우선, 형식 오류 메시지.
- 혼잣말: 말하지 않는 조건들, 사건 대사 쿨다운, 6초 초과 시 예비 대사, 첫 문장·60자 자르기, 반복 회피, 실패 시 오류 문구 없음. 기존 `tests/test_app.py`의 가짜 worker 방식을 그대로 쓴다.

## 만드는 사람에게 맡기는 것

- 각 값의 정확한 변화 속도와 경계값. 위의 수치는 출발점이다. 개발자 패널로 보면서 맞춘다.
- `personality.toml`의 배율과 예비 대사 문장 전체(페비 말투는 `Modelfile`의 [말투]를 따른다). 기본 `personality.toml`은 placeholder와 phoebe 동작 이름을 함께 다룬다.
- 상황 설명 문장의 정확한 표현.
- `Mood`를 `Pet`이 가질지 `PetApp`이 가질지. 단, 동작 고르기와 사건 감지가 `Pet` 안에 있으므로 `Pet`이 갖고 `PetApp`이 읽는 쪽을 권한다.
